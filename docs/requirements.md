# 장터온 요구사항 명세

> [plan.md](./plan.md)는 서비스의 전체 비전(공모전/사업계획서용)을 담고 있습니다. 이 문서는 그 중 **이번에 실제로 웹으로 만들 것**을 구체적으로 정의합니다. plan.md의 기능 중 실제 운영(결제대행, 배송 기사, 콜센터 등)이 필요한 부분은 화면으로만 흉내내거나 이번 범위에서 제외합니다.

## 1. 이미 구현된 것 (현재 코드 기준)

주문 흐름: **홈 → 물품선택 → 배송일 → 배송지 → 결제방법 → 주문완료** (5단계, `src/app/page.tsx`)

- **홈 화면**: "화면 보고 고르기" / "소리 듣고 고르기" 모드 선택, 인사 음성 안내
- **물품선택 화면**: 채소·과일·쌀·물·생활용품·간식·약과 건강용품 카테고리, 품목별 옵션(용량/종류)과 가격, 수량조절(+/−), 담은 목록에서 바로 수량조절, "기타" 물품 추가(음성으로 이름 말하기 → 확인 → 더 있는지 묻기, 또는 직접입력 + 한글 큰 키패드)
- **배송일 화면**: 오늘/내일/다른 날짜, 커스텀 달력(연도 포함), 음성으로 날짜 말하기(예: "8월 15일") 인식 및 재확인
- **배송지 화면**: 텍스트 입력 또는 음성 입력(연속 인식, 긴 시간 대기)
- **결제방법 화면**: "만나서 결제" / "카드 결제" 중 선택 — 실제 결제 연동은 없음
- **주문완료 화면**: 실제 배송 날짜를 포함한 음성 안내("가까운 가게에 알림을 보냈고 ○월 ○일에 배달해드려요")
- **공통 접근성**: 전체 화면 음성 안내(TTS), 일정 시간 지나면 안내 반복, "다시 듣기" 버튼, 읽어주기 켜기/끄기, 음성 인식(마이크)으로 답하기, 뒤로가기

## 2. 이번에 추가로 만들 것 (초안 — 확인 필요)

- **메인 화면**: 카테고리 바로가기, 자주 구매한 상품, 오늘 배송 예정 등
- **공동배송 화면**: "지금 함께 주문 중인 이웃 수", "배송 예정 시간" 등을 보여주는 화면 — 실제 매칭 로직 없이 예시(가상) 데이터로 구성
- **자주 구매한 상품 원터치 재주문**
- **AI 공동배송 매칭 데모 (핵심 기능)**: 진주 외곽지역 동네 중 하나를 무작위로 골라 허브로 삼고, 그 주변 500m 이내에 배송지 3~4곳을 무작위로 생성한 뒤, 실제 도로 기반 길찾기 API(카카오모빌리티 등)로 방문 순서를 최적화하는 배송 경로를 계산한다. 실제 서비스에 붙는 기능이자 공모전 발표자료에도 쓰이는 코드로, 실제 주소/주문 데이터 대신 데모용 무작위 좌표를 사용한다 (실사용자 매칭 큐·실시간 주문 묶기 로직은 이번 범위 밖).

## 3. 이번 범위에서 제외 (화면만 흉내내거나 만들지 않음)

- **결제**: 실제 카드사/결제대행사 연동 없음. "결제 완료" 화면만 (이미 구현됨)
- **전화 주문 접수**: 실제 콜센터 연결 없음
- **배송 협력 기사 배차**: 실제 인력 운영이 필요해 학생 프로젝트로 불가능 — 화면상 표시만
- **지역 상인 실제 제휴/재고 연동**: 실제 계약이나 재고 시스템 연동 없음. 더미 데이터 사용

(배경: 실제 운송/배송 운영은 별도 사업자 등록·면허·인력 없이는 만들 수 없다는 제약이 있음 — plan.md의 비전과 실제 구현 범위를 분리하는 이유)
